## 🎯 Bug Hunting Checklist per Component

When starting TDD on a component, check these common bug patterns:

### For **Interactive Components** (RetailFnBar, ProductGrid, Topology nodes):
- [ ] Keyboard navigation (Tab, Arrow keys, Enter, Escape)
- [ ] Focus management (traps, restoration, visible focus rings)
- [ ] Touch targets ≥ 48×48dp (mobile)
- [ ] Double-click vs single-click discrimination
- [ ] Drag threshold (prevent accidental drag on click)
- [ ] Loading/disabled states during async operations
- [ ] Error boundaries / graceful degradation
- [ ] i18n: RTL layout, text overflow, number/date formatting
- [ ] Reduced motion preference respected

### For **Data Display** (AnalyticsCardContent, TopologyMinimap):
- [ ] Empty state handling
- [ ] Loading skeletons (not spinners in lists)
- [ ] Number formatting (locale, compact notation, currency)
- [ ] Truncation with tooltip/ellipsis
- [ ] Real-time updates don't cause layout shift
- [ ] Color contrast (WCAG AA)

### For **Forms/Modals** (EmailReportSettings, LicenseSettings, RetailModals):
- [ ] Validation on blur + submit
- [ ] Dirty state tracking (unsaved changes warning)
- [ ] Auto-save / debounce
- [ ] Focus trap + Escape to close
- [ ] Portal cleanup on unmount
- [ ] Nested modal stacking (z-index, focus)
- [ ] Cron/date/time input validation

### For **Hooks** (useKeyboardAvoidance, usePullToRefresh):
- [ ] Cleanup on unmount (listeners, observers, timeouts)
- [ ] SSR safety (no `window`/`document` access)
- [ ] Memory leaks (event listener deduplication)
- [ ] Race conditions (rapid trigger/cancel)
- [ ] Platform differences (iOS vs Android keyboard)
- [ ] Reduced motion / accessibility settings

## 📝 TDD Cycle Template

When picking a new area:

```
Phase 1: Analyze
  □ Read component + existing tests
  □ Identify smallest valuable slice
  □ Write behavior sentence: "When X, system must Y"

Phase 2: Find Weaknesses
  □ Check checklist above for relevant patterns
  □ Look for: unwrap()/expect(), missing error boundaries, console.error
  □ Reproduce in failing test first

Phase 3: Red → Green → Refactor
  □ Write failing test (Red)
  □ Minimal implementation (Green)
  □ Clean up with tests passing (Refactor)

Phase 4: Verify
  □ npm run test -- <file>
  □ npm run lint && npm run typecheck
  □ Area-scoped tests (test-changed.sh)

Phase 5: Journal
  □ Append to JOURNAL.md

Phase 6: Update Docs
  □ Update this file (TEST_COVERAGE_ANALYSIS.md)
  □ Check skill-drift-guard if touching skill paths

Phase 7: Commit
  □ Conventional commit message
  □ Small, focused, well-described
```
