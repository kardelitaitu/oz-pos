# Revenue Data Pipeline — Paddle + Midtrans

**Goal:** Replace the admin dashboard's price-map MRR estimation with real transaction amounts from Paddle (USD) and Midtrans (IDR).

## Architecture

```
Paddle webhook (transaction.completed)   Midtrans webhook (settlement)
       ↓                                        ↓
  Parse amount + currency_code             Parse gross_amount (IDR)
       ↓                                        ↓
  Write revenue_events record              Write revenue_events record
       ↓                                        ↓
  /api/v1/admin/stats: sum revenue_events + FX conversion (USD→IDR)
```

## `revenue_events` collection schema

| Field | Type | Description |
|---|---|---|
| id | text (autogenerated) | PK |
| tenant_id | relation → tenants | The tenant who paid |
| event_id | text | Paddle event_id or Midtrans transaction_id (dedup) |
| provider | select | "paddle" or "midtrans" |
| amount_usd | number | USD amount (Paddle: from unit_totals, Midtrans: converted via FX) |
| amount_idr | number | IDR amount (Midtrans: gross_amount directly, Paddle: converted via FX) |
| currency | text | "USD" or "IDR" (original charge currency) |
| tier_key | select | plus/pro/premium/enterprise |
| subscription_id | text | paddle_sub_id or midtrans_sub_id |
| notes | text | Transaction metadata (payment_type, etc.) |
| created | autodate | When the event was recorded |

## Implementation phases

### Phase A — Schema + helper (this PR)
1. Add `revenue_events` to `pb_schema.json`
2. Create `revenue_events.go` with `saveRevenueEvent(app, event)` helper
3. Add `revenue_events` to test collections in handler_test.go / dashboard_api_test.go

### Phase B — Paddle capture
4. Wire `transaction.completed` in `paddle_webhook.go` to call `saveRevenueEvent`
5. Parse the Paddle transaction payload for amount/currency

### Phase C — Midtrans capture
6. Wire `settlement` / `capture` status in `midtrans_webhook.go` to call `saveRevenueEvent`
7. Parse gross_amount (already IDR, no conversion needed)

### Phase D — Stats endpoint
8. Update `/api/v1/admin/stats` to sum `revenue_events` for MRR and monthly gross
9. Keep the price-map as fallback when no revenue_events exist (new tenants)

## Notes

- Midtrans `gross_amount` is in IDR (integer, no decimal — e.g. "199000" for Rp 199.000)
- Paddle amounts are in USD cents (decimal — e.g. 499 for $4.99)
- The `event_id` is used for dedup (Paddle retries, Midtrans may resend)
- FX conversion: Paddle USD → IDR uses the server-side cached FX rate
- The stats endpoint should sum revenue_events by month, provider-aware
